# browserCAD

Браузерный просмотрщик 3D-моделей с инструментами измерения, сечений и преобразования модели. Позволяет открывать полигональные модели и просматривать инженерные STEP-файлы после конвертации в GLB на сервере.

**Live demo: [browsercad.ru](https://browsercad.ru)**

## Возможности

- Загрузка файлов и папок через диалог выбора или drag-and-drop.
- Просмотр модели с вращением камеры, масштабированием и панорамированием.
- Перемещение, поворот и масштабирование модели, сброс преобразований.
- Горизонтальные и вертикальные сечения с настройкой положения плоскостей.
- Отображение габаритов по осям X, Y и Z с выбором единиц измерения.
- Измерение расстояния между двумя точками модели.
- Выделение объектов и просмотр их свойств.
- Конвертация STEP → GLB с помощью OpenCASCADE и отображение инженерных метрик: объёма, площади, габаритов, количества тел, граней и треугольников.

## Поддерживаемые форматы

| Формат | Обработка |
| --- | --- |
| `.glb` | Открывается в браузере |
| `.gltf` | Открывается в браузере; внешние буферы и текстуры нужно загрузить вместе с моделью |
| `.stl` | Открывается в браузере |
| `.step`, `.stp` | Отправляется на сервер для конвертации в GLB |

Для `.gltf` с внешними ресурсами удобно выбирать папку с моделью, сохраняя структуру файлов. Объём и площадь для STEP вычисляются по исходной B-Rep-геометрии, до преобразования в полигональную сетку.

## Технологии

- **Фронтенд:** React 19, TypeScript, Vite 7, three.js, Chakra UI 3, Framer Motion.
- **Конвертация STEP:** Python 3.14, Flask, OpenCASCADE через `cadquery-ocp`.
- **Развиваемая архитектура бэкенда:** Flask + Celery + Redis, nginx и systemd для развёртывания.

## Локальный запуск

### Просмотр GLB, glTF и STL

Требуются Node.js 20.19+ в ветке 20.x либо 22.12+ и npm.

Из корня репозитория:

```bash
cd frontend
npm ci
npm run dev
```

Откройте адрес, который Vite выведет в терминале (по умолчанию — `http://localhost:5173`). Для просмотра GLB, glTF и STL запуск бэкенда не требуется.

### Конвертация STEP

В отдельном терминале из корня репозитория создайте Python-окружение и запустите демо-сервер:

```bash
cd backend
python3.14 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python demo_server.py
```

Сервер слушает `http://localhost:8000`. Vite уже настроен проксировать запросы `/api` на этот адрес. При работающем фронтенде выберите файл `.step` или `.stp` — после конвертации модель откроется в просмотрщике.

Проверить доступность API можно командой:

```bash
curl http://localhost:8000/api/ping
```

Текущий демо-сервер выполняет конвертацию синхронно через `POST /api/convert` и возвращает GLB с метриками в заголовке `X-Meta`. Для этого режима Redis и Celery не нужны.

Асинхронный API с очередью задач находится в разработке. Его архитектура, настройки и дорожная карта описаны в [документации бэкенда](backend/README.md); учебные заготовки помечены `TODO (Урок ...)`.

## Команды фронтенда

Все команды выполняются из каталога `frontend/`.

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Сервер разработки |
| `npm run build` | Проверка TypeScript и сборка в `frontend/dist/` |
| `npm run preview` | Локальный просмотр собранного фронтенда |
| `npm run lint` | Проверка ESLint |

В проекте есть известные замечания ESLint в коде выделения объектов и UI-сниппетах. Отдельного тестового раннера нет.

## Развёртывание

Push в ветку `main` запускает автоматический деплой фронтенда: GitHub Actions подключается к серверу по SSH и выполняет расположенный на сервере `deploy.sh`.

Бэкенд развёртывается отдельно вручную. Конфигурации и скрипт находятся в [`backend/deploy/`](backend/deploy/), подробности — в [документации бэкенда](backend/README.md#9-деплой-без-docker-вручную-по-ssh).
